# Панель на роутере и «доктор» — план

Цель: с любого телефона дома открыть страницу роутера и увидеть, что работает. Если тормозит YouTube,
там же переключить туннель. Если не открывается сайт — ввести адрес, и доктор скажет, в чём дело, а
кнопка «Исправить» добавит сайт в обход.

## Экран (один, крупно)

```
 switchback                         [обновить]
 ● YouTube            работает · zapret
 ● Telegram           работает · туннель
 ● Instagram          медленно · туннель
 ● ChatGPT и Claude   работает · напрямую
 ● сайт example.org   не открывается · туннель

 Туннель: Wireguard0 (работает)
 Запасные: Wireguard1, Wireguard2
 [ Переключить на следующий ]

 Не открывается сайт?
 [ example.com        ] [ Проверить ]
   ✓ Интернет есть
   ✓ Адрес сайта находится
   ✗ Напрямую не открывается
   ✓ Через туннель открывается
   → Пустить через туннель   [ Исправить ]
```

Точки: зелёная — страница пришла целиком, жёлтая — пришла медленно или оборвалась, красная — не открывается.
«Как идёт»: напрямую / zapret / туннель. Подробности (имя туннеля, время ответа) показываются только по нажатию на строку.

## Файлы

- `lib/panel.sh` содержит две части:
  - команду установщика `panel on|off|status|link|state|next`;
  - доктор сайта `sites doctor ДОМЕН`.
- `panel/index.html` — страница целиком: свой CSS и JS, без CDN, около 10 КБ.
- `panel/sb.cgi` — CGI на sh: вход, защита и вызов команд установщика. Своей логики проверок в нём нет.
- `lib/bot.sh`: `/diag ДОМЕН` и присланная ссылка идут через того же доктора, кнопки берутся из его ответа.
- Минутное задание `sb-panel` поднимает веб-сервер после перезагрузки или падения.

## Сервер

- `httpd` из busybox: на Keenetic это busybox Entware, на OpenWrt — busybox с httpd, если он есть.
- Если httpd нет, на OpenWrt используется `uhttpd` (он есть почти везде вместе с LuCI), отдельным процессом.
- Порт 8088. Сервер слушает **только адрес роутера в домашней сети** (например `192.168.1.1:8088`).

## Безопасность

- **Только домашняя сеть.**
  - Сервер привязан к адресу LAN.
  - CGI дополнительно отказывает, если адрес клиента не частный (10/8, 172.16/12, 192.168/16).
- **Вход по токену.**
  - Установщик генерирует токен: 128 бит из `/dev/urandom`, файл с доступом только для root.
  - Ссылка вида `http://192.168.1.1:8088/#t=ТОКЕН`. Токен стоит после `#`, поэтому не попадает в журналы сервера.
  - Страница один раз отправляет его POST-запросом и получает cookie сессии: `HttpOnly`, `SameSite=Strict`, 30 дней.
  - Пароль роутера не нужен и не используется. `panel link` показывает ссылку снова, `panel token` выдаёт новую и сбрасывает все входы.
- **Изменения только через POST, с CSRF-токеном.** Он выдаётся вместе с сессией и проверяется в теле запроса.
  Проверка сервисов — GET, она ничего не меняет.
- **Ввод только по белому списку.**
  - Домен: `a-z 0-9 . -`, и затем ещё `site_valid`.
  - Способ: `zapret|vpn|dns`.
  - Действие: из фиксированного списка.
  - Значения не попадают ни в `eval`, ни в shell без кавычек. Тело запроса — не больше 2 КБ.
- Заголовки: `X-Frame-Options: DENY`, `Content-Security-Policy: default-src 'self'`, `no-store`, `nosniff`.

## Память (KN-1710, 128 МБ)

- Сервер в покое: около 0,3–0,5 МБ.
- Во время запроса: CGI и один запуск `install.sh` занимают около 2–4 МБ на несколько секунд.
- Проверка сервисов идёт параллельно, по одному `curl` на сервис (около 1 МБ каждый), не дольше 10 с.
  Результат кешируется на 60 с.
- Фоновой нагрузки нет: минутное задание только проверяет, жив ли сервер.

## Включение

- По умолчанию выключено.
- Включается одним из способов:
  - модуль `panel` в «Выбрать модули вручную» (по умолчанию «нет»);
  - `modules=... panel` в файле ответов;
  - команда `sh install.sh panel on`.
- Выключение — `panel off`. «Откатить всё» тоже убирает панель: сервер, задание и токен.

## Не входит в первую версию

- Кнопка в программе для Windows: сейчас ссылку показывает установщик.
- HTTPS: внутри дома и при токене обходимся HTTP.
- Выбор конкретного туннеля: есть только «на следующий».
- Подбор способа для QUIC сам по себе. Сейчас (0.7.6) это вручную: `tune quic next|undo|status` и кнопка в боте,
  оценку по байтам человек смотрит сам. Дальше можно так: после `next` запомнить байты по udp/443 из
  `/proc/net/nf_conntrack` (по серверам, только устройства дома), через 2 минуты сравнить и сказать «лучше / хуже,
  вернуть?». Сложность — нужно, чтобы кто-то в это время смотрел видео; без него байт нет и сравнивать нечего.
  Кэш провайдера (188.234.130.x у нашего) стоит не считать: он отдаёт МБ при любом способе.
  Ещё QUIC-способ можно показать на панели рядом с zapret.
