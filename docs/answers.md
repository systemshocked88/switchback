# Установка без вопросов: файл ответов и строки прогресса

## Файл ответов

```sh
sh install.sh install --answers answers.txt
sh install.sh install --answers - < answers.txt     # из stdin: файл на роутере не появляется
```

Формат: строки `КЛЮЧ=ЗНАЧЕНИЕ`, строки с `#` — комментарии, кавычки вокруг значения можно не ставить,
переносы строк Windows (CRLF) понимаются. Если в файле неизвестный ключ или строка без `=`, установщик
сразу останавливается (код 2) и ничего не меняет — так опечатка не превратится в «ответ по умолчанию».
Сами значения на экран не выводятся (в файле может быть токен бота).

**Вопрос, на который в файле нет ответа, получает ответ по умолчанию** — с клавиатуры ничего не читается.
Исключение — DNS: без ответов по умолчанию «да», с файлом ответов настраиваются только сервисы,
названные в нём (`dns_chatgpt=y`), потому что без адреса сервера настроить всё равно нельзя.

| Ключ | Значения | По умолчанию | Что это |
|---|---|---|---|
| `profile` | `full` `zapret` `dns` `vpn` `custom` | `full` | что ставить (то же, что `--profile`) |
| `modules` | список через пробел: `https zapret dns nodes vpn meta watchdog failover panel` | — | модули для `profile=custom`; порядок всегда безопасный, какой бы ни был в файле |
| `continue_with_warnings` | `y` / `n` | `y` | продолжать, если анализ нашёл предупреждения |
| `continue_with_problems` | `y` / `n` | `n` | продолжать, если анализ нашёл серьёзные проблемы |
| `start` | `y` / `n` | `y` | «Начинаем?» после плана |
| `zapret_exclude_policy` | имя политики | пусто | Keenetic: политика доступа, устройства в которой zapret не трогает |
| `disable_offload` | `y` / `n` | `y` | OpenWrt: выключить flow offloading (иначе zapret не работает) |
| `no_quic` | `y` / `n` | `y` | запретить устройствам дома QUIC (UDP 443): иначе приложение YouTube может не грузить видео. `n` — если дома есть свой VPN через UDP 443 |
| `dns_chatgpt`, `dns_claude` | `y` / `n` | `n` | настраивать DNS для сервиса |
| `dns_chatgpt_ip`, `dns_claude_ip` | IPv4 | — | Keenetic: IP DoT-сервера |
| `dns_chatgpt_sni`, `dns_claude_sni` | имя | — | Keenetic: имя (SNI) DoT-сервера |
| `dns_chatgpt_doh`, `dns_claude_doh` | `https://…/dns-query` | — | OpenWrt: адрес DoH |
| `ai_reserve` | `y` / `n` | `n` | резерв для нейросетей (Claude, ChatGPT): если сайт перестал открываться, роутер сам переходит на другой путь — Zapret DNS, запасные адреса (`lists/ai-*-proxies.nets`), VPN — и пишет в бот и ntfy. Вручную: `sh install.sh ai via vpn` / `ai next` / `ai auto`, в боте `/ai` |
| `vpn_iface` | имя подключения | первое найденное | через какое WireGuard пускать Telegram (Keenetic: `Wireguard0`, OpenWrt: `wg0`) |
| `meta_vpn` | `y` / `n` | `y` | модуль `meta`: пускать Instagram, Facebook, WhatsApp и Threads через тот же туннель, что Telegram (сети Meta + DNS 1.1.1.1 через туннель) |
| `bot_token` | токен от @BotFather | — | без него модуль «сторож и бэкап» пропускается с предупреждением |
| `ntfy_url` | `https://ntfy.sh/длинное-имя` (от 12 знаков) или пусто | без файла ответов — создать новый | запасной канал уведомлений ntfy: сообщения уходят туда, если Telegram не ответил; можно и без бота |
| `bot_chat` | число | узнаётся через `getUpdates` | номер чата для уведомлений |
| `failover_tunnels` | список через пробел | все подключения WireGuard | Keenetic: туннели для автосмены по порядку (первый — основной) |
| `replace_watchdog`, `replace_backup`, `replace_failover`, `replace_nodes`, `replace_bot` | `y` / `n` | `n` | заменять уже существующие чужие скрипты (оригинал сохраняется) |
| `uninstall_confirm` | `y` / `n` | `n` | подтверждение отката (`install.sh uninstall`) |
| `uninstall_packages` | `y` / `n` | `n` | при откате удалить и пакеты, поставленные установщиком |
| `uninstall_feeds` | `y` / `n` | `n` | при откате вернуть источники пакетов на http |

Пример для Keenetic:

```
profile=full
zapret_exclude_policy=nfqws
dns_claude=y
dns_claude_ip=203.0.113.10
dns_claude_sni=dns.example.com
vpn_iface=Wireguard0
bot_token=123456789:AA...
```

## Строки прогресса (`--progress`)

Для программ, которые запускают установщик (switchback для Windows). Обычный текст печатается как
всегда, а между ним — служебные строки: `@@sb`, табуляция, событие, табуляция, поля.
`--progress` выключает цвета.

| Событие | Поля | Когда |
|---|---|---|
| `platform` | `keenetic` / `openwrt` / `merlin` / `unknown` | сразу после заставки |
| `section` | заголовок | начало раздела |
| `group` | заголовок | подраздел внутри анализа |
| `item` | `ok` / `skip` / `warn` / `bad` / `dry`, текст | каждая строка-результат |
| `vpn` | имя подключения WireGuard, `up` / `down` | анализ: какие VPN-подключения есть и есть ли свежее рукопожатие с сервером (по одному на строку) |
| `tgvia` | имя подключения | анализ: через какое подключение уже идут сети Telegram (сделано switchback или вручную) |
| `doctor` | итог `0`/`1`/`2`, число предупреждений, число проблем | конец анализа (0 — готово, 1 — есть предупреждения, 2 — не рекомендуется) |
| `plan` | модули по порядку | перед «Начинаем?» |
| `backup` | путь на роутере | снимок до установки сохранён |
| `step` | номер, всего, модуль, название | начало шага установки |
| `result` | `ok` / `skip` / `warn`, название, подробность | итог шага |
| `status` | итог `0`/`1`/`2`, предупреждения, проблемы | конец `install.sh status` |
| `wg` | имя подключения | `wg-import` создал подключение WireGuard |
| `report` | путь к отчёту на роутере | `install.sh report` собрал отчёт |
| `wg_check` | имя, `ok` / `notraffic` / `nohandshake` | `wg-import`: проверка нового туннеля настоящим трафиком |
| `fw` | прошивка (`keenetic`/`openwrt`), версия, OpenWrt: board_name (и модель) | анализ: какая прошивка стоит (программа подсказывает про обновление) |
| `ntfy` | адрес канала | анализ: запасной канал уже настроен на роутере; установка: канал записан |
| `installed` | версия на роутере (`old` — до 0.6.0), версия установщика | анализ и статус: switchback уже стоит; разные версии — пора обновить |
| `updated` | была, стала | `install.sh update` закончил (`none` — обновлять нечего) |
| `site` | способ (`zapret`/`dns`/`vpn`), сайт | `sites list`: свой сайт (по одному на строку) |
| `site_way` | `zapret`, или `vpn` и туннель | `sites list`: способ доступен на этом роутере |
| `site_dns` | сервис (`claude.ai`, `chatgpt.com`) | `sites list`: способ `dns` может взять DNS-сервер этого сервиса |
| `site_dnsfree` | число | `sites list`: сколько ещё DNS-записей примет роутер |
| `site_res` | сайт, `added`/`removed`/`exists`/`builtin`, способ | итог `sites add` / `sites del` |
| `site_check` | сайт, `ok`/`down`, код ответа, время, с | `sites check` |
| `doc` | шаг (`net`/`now`/`dns`/`zapret`/`vpn`), итог (`ok`/`bad`/`slow`/`cut`/`down`/`maybe`/`none`) | `sites doctor`: шаг проверки |
| `doc_say` | вывод простыми словами | `sites doctor` |
| `doc_fix` | способы для `sites add`, первый — главный | `sites doctor`: что поможет |
| `doc_end` | `device`/`vpn`/`zapret`/`dns`/`slow`/`down`/`nonet`/`bad` | итог `sites doctor` |
| `svc` | сервис, `green`/`yellow`/`red`, как идёт, слово | `panel state` |
| `tun` / `tun_switch` | туннель, `up`/`down`, `active`/`standby` / `yes`/`no` | `panel state` |
| `panel` | `on` и ссылка / `off` | `panel on|status|token|off` |
| `next` | туннель, `ok`/`fail` | `panel next` |
| `tune_try` | номер, всего, способ | `tune`: пробую способ |
| `tune_res` | способ (`сейчас` — до подбора), открылось, всего, скорость YouTube (байт/с) | `tune`: замер |
| `tune_done` | `applied` и записанные способы / `kept` / `undone` | итог `tune` |
| `fail` | сообщение | ошибка; дальше идёт автооткат |
| `end` | код выхода | самая последняя строка всегда |

Переменная `SB_ANSWERS_RM=1` (так запускает программа): файл ответов удаляется сразу после чтения.

Код выхода: `0` — успех (или отказ на вопросе), `1` — ошибка (изменения этого запуска откатились),
`2` — неверные параметры или файл ответов; у `doctor` код равен итогу анализа.

## Проверка

`sh tests/run.sh` — автотесты на поддельных роутерах (Keenetic и OpenWrt), в том числе файл ответов,
ответы из stdin, события, откат при сбое и то, что токен не попадает в вывод и журнал.
Без аргументов идут все группы тестов, до 4 одновременно, с самым низким приоритетом (компьютер не тормозит;
`SB_JOBS=1` — по одной). Только нужные группы: `sh tests/run.sh vless ai` (или `TESTS=vless,ai sh tests/run.sh`);
список групп: `sh tests/run.sh --list`.
